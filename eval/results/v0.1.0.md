# Evaluation results for v0.1.0

Measured on 2026-10-17 with OpenCode 2.0.27 and the harness in [`eval/`](../README.md).

## Setup

- **Tasks.** 30 tasks from SWE-bench Pro V2: three from each of ten repositories (NodeBB, ansible, element-web, flipt, vuls, teleport, openlibrary, navidrome, webclients, qutebrowser), in Go, Python, JavaScript, and TypeScript. `eval/tasks.json` lists them, and `eval/README.md` says how they were picked.
- **Models.** `opencode-go/glm-5.3-flash` and `opencode-go/deepseek-v4.1-flash` through OpenCode Go, and `openai/gpt-6.1-sol` and `openai/gpt-6-luna` through a ChatGPT login. All four ran with reasoning effort `high`.
- **Configurations.** A is OpenCode alone. B is OpenCode with lodestar. Every task ran once per model and configuration: 240 runs, or 120 pairs of A and B on the same task and model. All 240 counted.
- **Protocol.** Each run follows the benchmark's own rules. The agent works inside the task's container, with the network closed except for the model API, and gets 50 minutes. Its diff is then graded in a fresh container by the task's hidden tests.
- **Compaction.** Automatic compaction starts at 50,000 tokens. The models' windows are much larger, but these sessions rarely grow that far. Even at 50,000, only 89 of the 240 runs compacted.

- DeepSeek compacted most often and gained the most, in every measure.
- GLM read far fewer files again after compaction. It resolved three fewer tasks with lodestar, but in two of those three runs lodestar's session never compacted, so nothing was restored. That leaves chance as the likely cause, which one run per task can't rule out.
- GPT-6.1 Sol read files again about as often either way.
- GPT-6 Luna finished most tasks before reaching the threshold, so lodestar had nothing to restore.

## What else was checked

- **The recap request doesn't end runs early.** After eight tool calls in a row, lodestar asks the agent for a one-line recap. An agent that answers with text and no tool call ends its turn, so this could stop work early. Of the 120 B runs, 9 ended right after a recap request, and 8 of those 9 resolved their task.
- **Failures that only happened with lodestar.** In four of the five tasks resolved only without lodestar, lodestar's run never compacted, so lodestar had restored nothing.

## Limitations

- **Most tasks were solved either way.** OpenCode alone resolved 110 of 120, so this sample can't show a change in the resolve rate. Its effect shows in effort: tokens, tool calls, and files read again.
- **The savings are mostly cached tokens.** Uncached prompt tokens didn't fall. The restored files are new input after every compaction, which likely offsets the files the agent no longer reads again. The cost of the OpenCode Go runs fell 8%, which is within noise.
- **Compaction is forced early.** The 50,000-token threshold is far below what these models allow, to make compaction happen at all. In real sessions, compaction comes later and less often.
- **One run per task, model, and configuration.** Single pairs are noisy. The pooled numbers above are what to rely on.
- **Time includes contention.** Three runs ran at once, so a run's test commands shared CPU with others, which adds noise to minutes.

The runs cost $6.86 for the 120 OpenCode Go runs, and about 28 hours of agent time in total. The OpenAI runs went through a ChatGPT plan, which has no per-token price.
