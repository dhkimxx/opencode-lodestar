# Evaluation results: v0.3.0 with DeepSeek V4.1 Flash

Measured on 2026-10-21 with OpenCode 2.0.27 and the harness in [`eval/`](../README.md).

## Setup

- **Tasks.** The tasks in `eval/tasks-hard.json`, from SWE-bench Pro V2. They come from ten repositories: NodeBB, ansible, element-web, flipt, vuls, teleport, openlibrary, navidrome, webclients, and qutebrowser, in Go, Python, JavaScript, and TypeScript.
  - Each repository has three large tasks: the ones whose reference patch size is closest to that repository's 95th percentile, among the tasks that touch at least four files.
  - Each also has its largest task from HARD-51, a subset most model families fail.
  - `eval/README.md` says how they were picked.
- **Model.** `opencode-go/deepseek-v4.1-flash` through OpenCode Go, with reasoning effort `high`.
- **Configurations.** A is OpenCode alone. B is OpenCode with lodestar. Every task ran once per configuration. A run that ended in a provider error doesn't count, so the comparison covers the 28 tasks where both runs counted.
- **Protocol.** Each run follows the benchmark's own rules. The agent works inside the task's container, with the network closed except for the model API, and gets 50 minutes. Its diff is then graded in a fresh container by the task's hidden tests.
- **Compaction.** The harness compacts a session whenever a request reaches 40,000 tokens (`--compact-at 40000`). OpenCode's own compaction keeps its default threshold. This makes compaction happen often while OpenCode sends every compaction request as it is, the way it does in real sessions. In 20 of the 28 pairs, both runs compacted, many of them several times.

## Where the difference came from

- **Less re-reading.** After a compaction, lodestar puts back the request, the latest steps with what they returned, the files the agent changed, and the code it was reading. Agents read 71% fewer files again, and they made 41% fewer tool calls overall.
- **Fewer compactions.** With less re-reading, the context filled up more slowly: 3.0 compactions per run instead of 5.5. Each compaction costs a summary request and a new prompt prefix.
- **The prompt cache holds.** What lodestar restores goes into OpenCode's compaction request too, so the request matches the ones before it. Uncached prompt tokens fell 45%, about as much as prompt tokens overall.
- **The hardest tasks.** On the 8 HARD-51 tasks, A resolved 5 and B resolved 7. On the 20 large tasks, both resolved all 20.

## Limitations

- **One model.** These results are for DeepSeek V4.1 Flash through OpenCode Go.
- **The resolve rate isn't settled.** Three tasks went to lodestar and one against it. With 28 pairs, that is within chance (exact McNemar test, p = 0.63).
- **Compaction is forced early.** DeepSeek V4.1 Flash has a 1M-token window, and real sessions compact later and less often.
- **One run per task and configuration.** Single pairs are noisy. The pooled numbers above are what to rely on.
- **Time includes contention.** Three runs ran at once, so a run's test commands shared CPU with others, which adds noise to minutes.

The 56 runs cost $4.37 and took 11.6 hours of agent time.
