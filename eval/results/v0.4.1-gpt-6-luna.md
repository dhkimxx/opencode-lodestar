# Evaluation results: v0.4.1 with GPT-6 Luna

Measured on 2026-11-01 with OpenCode 2.2.5 and lodestar v0.4.1.

## Setup

- **Tasks.** Eleven tasks from SWE-bench Pro V2, listed in `eval/tasks-luna.json`. They are the tasks of `eval/tasks-hard.json` where DeepSeek V4.1 Flash compacted at least three times at 40,000 tokens, picked so that sessions compact often. They come from eight repositories (NodeBB, element-web, flipt, vuls, teleport, openlibrary, webclients, qutebrowser).
- **Model.** `gpt-6-luna` at reasoning effort `high`, through a ChatGPT login.
- **Configurations.** A is OpenCode alone. B is OpenCode with lodestar. Each task ran twice per configuration, which makes 22 pairs. They aren't independent: the two runs of a task share the task. A run that ended in a provider error doesn't count, and none did.
- **Protocol.** As in [the v0.3.0 results](v0.3.0-deepseek-v4.1-flash.md): the agent works in the task's container with the network closed except for the model API, gets 50 minutes, and is graded in a fresh container by the task's hidden tests.
- **Compaction.** OpenCode's own compaction, set to start at 26,000 tokens, so that most runs compact.
- **Cost.** Through a ChatGPT login nothing is billed per token. Cost here is the token counts OpenCode reports, at the model's list prices: $0.10 per million input tokens, $0.01 per million cached input tokens, and $0.50 per million output tokens, reasoning included.
- **Minutes.** The agent's working time, from its first event to its last.

## Results

Means per run, over the 22 pairs.

| Per run | A (OpenCode alone) | B (with lodestar) | Change | B minus A (95% interval) |
| --- | --- | --- | --- | --- |
| Tasks resolved | 10 of 22 | 15 of 22 | | |
| Cost | $0.039 | $0.058 | +50% | $0.019 ($0.003 to $0.040) |
| Cost per resolved task | $0.085 | $0.085 | 0% | |
| Prompt tokens | 1,013k | 1,333k | +32% | 320k (−31k to 735k) |
| Uncached prompt tokens | 232k | 370k | +60% | 138k (28k to 282k) |
| Output tokens | 15.0k | 22.0k | +47% | 7.1k (1.6k to 14.0k) |
| Tool calls | 94 | 121 | +28% | 27 (−3 to 67) |
| Files read again after compaction | 23.0 | 34.6 | +51% | 11.7 (−0.3 to 27.8) |
| Compactions | 6.4 | 10.4 | +62% | 4.0 (0.6 to 8.5) |
| Minutes | 7.4 | 9.4 | +26% | 1.9 (0.4 to 3.6) |

The intervals come from resampling the 22 pairs. Tool calls and re-reads count shell commands that print files (`cat`, `sed -n`) as well as the `read` tool, so they aren't comparable with the v0.3.0 rows, which count only the `read` tool. Cost per resolved task is total cost divided by tasks resolved.

## What to take from it

- lodestar resolved more tasks. In 6 of the 22 pairs only B resolved the task, in 1 only A did, in 9 both did, and in 6 neither did. B led in both rounds, 7 against 6 and 8 against 4. The difference is consistent but not settled: 22 pairs from 11 tasks can't rule out chance.
- Per run it spends 50% more. Per resolved task the cost is the same.
- On the tasks both resolved, lodestar spent less. In those 9 pairs B cost $0.017 against $0.022 for A, with 43 tool calls against 54 and 2.2 compactions against 3.3.
- The extra cost comes from the tasks neither resolved. In those 6 pairs B kept working where A stopped: 196 tool calls against 88, 20 compactions against 5.5, and $0.101 against $0.030.
- What lodestar restores stays in the prompt until the next compaction, so the context fills sooner: 8.6 compactions per 100 tool calls against 6.8. At 26,000 tokens the restoration takes about a fifth of the room a compaction frees.
- The tasks were picked for compacting often, so they favor what lodestar does.
